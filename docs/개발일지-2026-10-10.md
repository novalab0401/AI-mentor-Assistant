## 1. 출발점과 목표

- 전체 로드맵 1단계 「전공 소개 자체 검증」의 실제 작동하는 시스템 구현에 착수.
- 원칙: **속도보다 실력을 남기는 개발** — 단계별로 코드의 의미를 이해하며 진행.
- 앱 대신 **모바일 웹**(설치·심사 불필요, 링크로 접속), 로컬 LLM 대신 **상용 LLM**(추후 AI 채점 단계).
- 하루 동안 "시연 한 번 평가하는 도구" → "단체 전체가 사이트 안에서 돌아가는 멘토 역량 강화 플랫폼"으로 범위가 확장됨.

## 3. 진행 단계 (시간순)

### 1단계 — 개발 환경
- Node.js 설치, `create-next-app`으로 프로젝트 생성, 첫 화면 수정으로 동작 확인.

### 2단계 — 평가 입력 화면
- 휴대폰 크기 평가 화면: 항목별 1~4점 버튼 + 근거 메모.
- 학습 포인트: `"use client"`, `useState`, `map`으로 항목 반복 렌더링.

### 3단계 — DB 저장
- Supabase `evaluations` 표 생성, **평가자 1명 × 항목 1개 = 1줄** 구조(항목별 사람-AI 비교를 위해).
- `check (score between 1 and 4)`로 DB 차원에서 잘못된 값 차단.
- RLS를 켜고 "저장만 허용, 조회 불가"로 시작 → 봉인 규칙의 기초.
- `.env.local`로 키 분리(secret key는 절대 브라우저에 두지 않음).

### 4단계 — 시연(세션)과 평가 연결
- 사용자 지적: "누구의 시연을 평가했는지 알아야 한다" → `sessions` 표 + 외래 키(`session_id`).
- 시연 ID는 추측 불가능한 uuid, 화면 표시는 `시연 #번호`.
- 동적 라우팅(`/evaluate/[sessionId]`), 시연 목록·결과 화면, 시연 생성 후 평가 화면으로 자동 이동.
- 평가·시연 수정/삭제, 뒤로 가기, "평가받는 사람 vs 평가하는 사람" 문구 정리(전공은 선택 입력).

### 5단계 — 잠금(운영자 로그인 + 봉인)
- 운영자 로그인(Supabase Auth). 평가하는 선배는 로그인 없이 링크로 **제출만** 가능.
- 선배는 시연 표 전체를 볼 수 없고, 링크의 시연 1건 정보만 DB 함수(`security definer`)로 제공.
- 제출 후 결과 대신 "제출 완료" 화면 → 다른 평가자 점수를 볼 수 없음(봉인).

### 6~7단계 — 평가지 확장과 평가지 선택
- 공통 루브릭 v1 강사 항목 **원문 그대로** 사용(2층 구조의 고정 층).
- 공통 루브릭 적용표에 따라 "일반 모의수업"에서 채점 불가한 항목(반응 조절, 피드백 등)은 제외.
- △ 항목에 **"판단하기 어려움"(N/A)** — 0점이 아니라 평균에서 제외.
- 점수를 누르면 그 점수의 **기준 문장**이 표시됨 → 평가자 간 기준 맞추기.
- 서술형 칸: PPT 의견, 수업 내용 의견, 잘한 점, 다음에 바꿀 점.
- **평가지 3종** (수업 등록 시 선택):
  | 평가지 | 점수 항목 |
  |---|---|
  | 전공·진로 소개 · 모의 시연 | 공통 5 + 전공 정보 정확성, PPT 적절성 (특화 2개는 초안) |
  | 이공계 실습 수업 · 모의 시연 | 공통 6 + 핵심 개념 정확성, 실습 안내 명확성 (초안) |
  | 이공계 실습 수업 · 실제 수업 | 공통 12 전체 + 핵심 개념 정확성 (초안) |
- 사용자 지적: "학생 중심성은 전공 소개 멘토링용이 아니다" → 전공 소개 평가지에서 제외(공통 루브릭 4-2 유형별 N/A 규칙).
- 같은 id = 같은 기준 → 수업 종류가 달라도 공통 항목은 비교 가능.
- 이미 평가가 있는 수업은 평가지 변경 불가(점수 정합성).

### 8단계 — 멘토 피드백 공유
- 평가받은 멘토가 보는 **피드백 전용 비밀 링크**(평가 링크와 별도).
- 평가자 이름은 DB 함수 안에서 "평가자 1, 2…"로 변환 → 화면 코드로도 실명 확인 불가(솔직한 피드백 보장).
- 운영자가 **공개/비공개** 스위치로 공개 시점 결정.
- 항목별 평균, 현재 수준 기준 문장, **"다음 목표"(한 단계 위 기준 문장)** 표시 → 점수가 아니라 다음 행동이 보이게.

### 9단계 — 계정·그룹(밴드)
- 사용자 요구: 멘토링 받는 사람(=수업에 나갈 **예비 멘토**)도 사이트에서 활동, 그룹 단위 운영, 밴드 형태.
- 이 사이트에서 회원가입(이름·이메일·비밀번호), 프로필 자동 생성.
- 그룹 가입 신청 → **운영진 승인 시 역할 부여**(운영진 / 선배(평가자) / 멘토 / 예비 멘토).
- 운영진 위임·역할 변경·내보내기, 그룹 나가기. **운영진 0명 방지**(DB 트리거).
- 그룹 찾기(전체 그룹 목록, 멤버 수, 내 상태).
- 로그인한 평가자는 이름 자동 입력.

### 10단계 — 그룹 안의 팀
- 사용자 지적: 그룹은 단체 전체, 그 안에 기수·멘토링팀 등 작은 그룹 필요.
- 결정: 팀은 운영진이 만들고, 멤버는 신청(승인) 또는 운영진·팀장이 바로 추가. **팀장** 있음, **여러 팀 동시 소속** 가능.
- 공개 범위: 수업 목록은 그룹 전체 공개, **평가 결과는 그룹 운영진과 그 팀의 팀장만**.
- 팀장은 자기 팀 수업 등록·결과 열람·피드백 공개 가능. 그룹 탈퇴 시 팀에서도 자동 제외.

### 11단계 — Nova Lab 소유 구조와 데이터 보존
- 사업 모델 반영: 여러 단체가 구독해서 사용.
- 1차안(그룹 생성 개수 할당) → 사용자 제안으로 변경: **그룹은 Nova Lab 관리자가 만들어 그룹장(이메일)을 지정해 넘겨줌.**
- **그룹 삭제는 Nova Lab만** 가능.
- 수업·평가 삭제는 **보관 삭제(soft delete, `deleted_at`)** → 화면에서만 사라지고 DB에 보존. 진짜 삭제 권한은 아무에게도 없음(대시보드 제외).
- Nova Lab 관리자 화면: 전체 그룹·멤버·수업·평가 수, 그룹별 그룹장, 가입자 목록, 그룹 만들기.

## 6. 겪은 문제와 해결 (보고서의 "개발 과정" 근거)

| 문제 | 원인 | 해결 / 배운 점 |
|---|---|---|
| `Export supabase doesn't exist` | 파일 저장 안 함 | 저장 확인, 자동 저장 권장 |
| 프로젝트 URL에 `/rest/v1/` 포함 | 엔드포인트 주소 혼동 | 기본 주소만 사용, 라이브러리가 경로를 붙임 |
| `Could not find the table ... in the schema cache` | 이전 SQL이 섞여 전체 실패(트랜잭션 롤백) | **SQL은 항상 새 탭에서 실행**, 실패 시 전체 취소됨을 이해 |
| `new row violates row-level security policy` | 잠금 SQL 일부만 적용 | 규칙 목록 조회(`pg_policies`)로 진단 후 재실행 |
| Next.js `useParams` outside Suspense | Next.js 16 Cache Components | 서버 `page.tsx`가 Suspense로 감싸고 실제 화면은 클라이언트 파일로 분리 |
| instant navigation 경고 | 로그인 확인 동안 페이지를 그리지 않음 | 페이지는 그려 두고 확인 전에는 숨김 |
| RLS에 막힌 수정이 "성공"처럼 보임 | RLS는 에러 없이 0줄 처리 | 바뀐 줄 수를 확인하는 코드 추가 |
| 시연 삭제 시 외래 키 오류 | 점수→시연 연결에 cascade 없음 | `on delete cascade` 추가, 이후 보관 삭제로 전환 |
| push 시 Repository not found | 실제 레포 주소가 달랐음 | `git remote set-url`로 정정 |

## 9. 보고서에 쓸 만한 설계 포인트

- **2층 구조 루브릭의 구현**: 공통 항목은 코드에서 원문 고정(`COMMON`), 평가지는 항목 선택 + 특화 항목만 바꿈 → 수업 종류가 달라도 공통 항목 비교 가능.
- **N/A 처리**: 평가 장면 적용표(○/△/✕)를 평가지 구성과 "판단하기 어려움" 버튼으로 구현, 평균에서 제외.
- **평가자 보정 장치**: 점수 선택 시 기준 문장 즉시 표시.
- **봉인과 익명성**: 평가자는 제출만, 멘토 피드백은 DB 단에서 익명화, 공개 시점은 운영자 결정.
- **성장 지향 피드백**: 현재 수준 + "다음 목표" 기준 문장 제시.
- **멀티 테넌트 + 데이터 보존**: 단체(그룹) 단위 격리, Nova Lab이 그룹 생성·삭제 권한 보유, 보관 삭제로 데이터 자산 보존 → 데이터 플라이휠의 전제.
- **보안 원칙**: 모든 권한은 DB 보안 규칙에서 강제(화면 숨김에 의존하지 않음).
