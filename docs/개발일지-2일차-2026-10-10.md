## 2. 사용자 테스트에서 나온 문제와 해결

| 사용자 피드백 / 증상 | 원인 | 해결 |
|---|---|---|
| 그룹 화면 `Cannot read properties of null (reading 'id')` | 로그인 확인 중·로그아웃 직후 사용자 정보가 비어 있는데 멤버 목록이 내 id를 읽음 | 사용자 정보가 확인되기 전에는 그룹 화면을 그리지 않음 |
| Nova Lab이 그룹을 만들 때 "운영진 최소 1명" 오류 | 그룹장을 넣기 전에 만든 사람(관리자)을 먼저 빼서 운영진 0명 순간 발생 | 그룹장을 먼저 넣고 그다음 관리자 제외 |
| 이메일 인증 안 한 계정도 가입된 것으로 나옴, 고칠 방법 없음 | 인증 여부 미확인, 관리 기능 없음 | 그룹장 지정은 인증 계정만; 관리자 화면에 인증 여부·이름 수정·계정 삭제 |
| Nova Lab 관리자가 만든 그룹을 관리 못 함 | 관리자가 그 그룹 멤버가 아님 | **Nova Lab 관리자는 모든 그룹에서 운영진 권한** (보안 함수 `is_group_admin`, `is_group_member`에 반영) |
| 멘토로 넣은 사람이 팀 만들기 등 아무것도 못 함 | 관리 기능은 운영진 권한 (설계대로) | 역할별 권한 안내 추가, 그룹장 위임 구조 정리 |
| 그룹장에게 거의 전부 위임하되 삭제는 Nova Lab 승인 | — | 그룹장 = 운영진 + **보호**(Nova Lab만 변경·제외 가능), **이메일 초대**, **그룹 삭제 요청 → Nova Lab 승인/거절** |
| 탭 순서(수업 → 팀): 팀이 먼저여야 함 | — | **팀 → 수업 → 멤버**, 기본 탭 팀, 팀 카드에서 "이 팀의 수업 보기"로 이동 |
| 팀 가입 신청 시 `row-level security` 오류 | 그룹 멤버가 아닌 Nova Lab 관리자에게 신청 버튼이 보임 | 그룹 멤버에게만 신청 버튼 표시 (DB 규칙은 그대로 유지) |
| 평가 결과가 평가받은 사람에게 전달되지 않음 (이름만 입력) | 발표자가 계정과 연결되지 않음 | 수업 등록 시 **발표자를 그룹 멤버에서 선택** → 공개되면 본인 홈 **"내가 받은 평가"**에 자동 표시 |
| 회원가입 비밀번호 오입력 위험 | — | **비밀번호 보기(눈 아이콘)**, **비밀번호 확인 칸**과 일치 여부 표시 |

## 3. 추가된 DB 변경 (SQL)

- `12-owner-delegation.sql`: Nova Lab 관리자 전 그룹 권한, 그룹장 보호 트리거, 그룹 생성 순서 수정·인증 확인, `admin_set_owner`, `group_invite`, 삭제 요청(`request_group_deletion`, `cancel_group_deletion`), 관리자 목록 함수 갱신, `admin_rename_user`, `admin_delete_user`
- `13-presenter.sql`: `sessions.presenter_id`(그룹 멤버만 지정 가능), `my_feedback_list()`
- 그 밖에 대화 중 실행: 평가→시연 외래 키 `on delete cascade`

| 누가 | 할 수 있는 것 |

| 링크 평가자(비로그인) | 평가 제출만 |

## 5. 설계 판단 (보고서용)

- **위임과 통제의 분리**: 단체 운영은 그룹장에게 거의 전부 위임하되, 데이터를 잃는 행위(그룹 삭제)만 Nova Lab 승인으로 묶음. 수업·평가 삭제는 보관 삭제라 데이터가 남음 → 구독형 서비스의 데이터 자산 보존.
- **피드백 전달의 자동화**: 발표자를 계정과 연결해 링크 전달 없이 본인이 확인 → 피드백 도달률을 높이고, 향후 "내 성장 기록"(여러 시연 점수 변화)의 기반.
- **화면이 아니라 DB에서 권한 강제**: 버튼을 숨기는 것은 보조이고, 실제 차단은 RLS. 이번 팀 가입 오류도 DB 규칙은 올바르게 막았고 화면만 고침.
